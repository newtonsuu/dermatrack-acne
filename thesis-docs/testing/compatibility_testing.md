# 4.x Limited Mobile Compatibility Testing

## Introduction
Mobile compatibility testing verifies that the developed application can be installed and operated correctly across different devices, operating-system versions, screen sizes, and runtime environments, independent of its detailed feature behavior. Because the Android ecosystem is highly fragmented — varying in CPU architecture, screen resolution, OS version, and vendor customizations — compatibility testing is necessary to confirm that DermaTrack builds, installs, and presents a stable, responsive interface on its target platforms. This section focuses strictly on compatibility (build generation, installation readiness, layout responsiveness, and environment support) rather than on full functional correctness, which is covered in the functional and security testing sections.

This assessment is labelled **Limited Mobile Compatibility Testing** because runtime verification was performed at the **build level** (web compilation and Android release-APK generation), while execution on a broad range of **physical Android devices and emulators was not performed within its scope**. The device/emulator rows of the matrix are therefore provided to be completed by the developer using the available test hardware.

## Interpretation of results
Within the scope tested, DermaTrack demonstrates sound build-level compatibility with its target platforms. The web target compiled successfully, and the Android release build produced installable, architecture-specific APKs (64-bit ARM, 32-bit ARM, and x86_64) without error, indicating that the application is build-ready for the Android 10–14 range and installable down to the configured minimum of Android 5.0 (API 21). Earlier UI testing also identified and corrected horizontal layout-overflow issues, improving responsiveness on narrow widths and large text scales. These results confirm that the application can be generated and deployed for its intended environments. However, the present assessment does not establish runtime compatibility across the diversity of physical Android devices; therefore, compatibility is confirmed only at the build level and within any environments subsequently verified by the developer. The findings should be read as evidence of deployment readiness rather than of validated cross-device runtime behavior.

## Limitation statement
This is a **limited** compatibility test. No physical Android device or emulator run was included within the automated assessment; results are substantiated only for **web build compilation** and **Android release-APK generation**, and the device/emulator rows are provided as a template for the developer to complete on available hardware. Consequently, **compatibility is confirmed only within the tested (build-level) environments**, and device-dependent features — camera capture, OS-level notifications/reminders, and PDF report sharing — require on-device verification that was outside this scope. A **broader device compatibility matrix is recommended for future work**, covering multiple manufacturers (e.g., Samsung, Xiaomi, OPPO), Android versions 8 through 14, a range of screen sizes including tablets, and both low- and high-end hardware, ideally complemented by automated instrumentation tests (Flutter `integration_test`) executed on a device farm.
